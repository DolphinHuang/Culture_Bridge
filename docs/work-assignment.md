# Culture Bridge MVP — 工作分配表

## 一、A 負責的工作

**基礎設施（Google Cloud）**
1. 建立 Google Cloud 專案（culture-bridge）、啟用試用額度，設定費用警報
2. 建開發環境：Cloud SQL for PostgreSQL 資料庫（含組員帳號、授權 IP、自動備份）、後端主機
3. 2026-11-10 前把資料庫從 30 天免費試用執行個體搬到最小規格的執行個體（匯出再匯入）
4. 申請網域、設定 HTTPS
5. 申請 Gemini 金鑰，設定用量上限
6. 設定登入服務（供應商【待確認】）
7. 建正式環境、開自動備份、管理環境變數
8. 裝錯誤監控（伺服器錯誤、App 閃退）
9. 部署 Web 版（伺服器須把不存在的路徑回傳 index.html）【待確認是否要做】

**專案設定**
10. 訂 repo 分支規則（PR 由另一人檢查）；設定 CI 自動跑 flutter analyze、flutter test 與後端測試（pytest）

**AI 助理（寫在 backend/ 的 Python FastAPI 後端，參考 Just Join backend/app/agent/）**
11. 對話 API 與工具呼叫：用 Gemini 的 function calling，每次回答前都透過工具查真實資料；工具沒有資料就直說，不能推測
12. 助理工具：搜尋流程、讀流程詳情（驗證狀態、來源、最後驗證時間、近期成功回報）、搜尋公開經驗、讀經驗、讀我的辦理進度
13. 回答規則（依 product-map 第 14～16 節）：標明依據與驗證狀態；回答優先順序為已驗證知識 → 流程卡 → 官方來源 → 學生經驗；經驗只能當學生經驗引用，不能說成事實；依介面語言回覆中文或英文
14. 知識庫：撰寫並載入 App 功能介紹、導覽說明、常見問題、名詞解釋（中英文），只用來說明 App 怎麼用；即時資料一律由工具提供
15. 對話記憶：同一個對話記住最近幾輪與上次搜尋結果，能理解「第二個」「這個流程」等接續語；不同帳號的對話互相隔離
16. 畫面動作：助理可回傳白名單內的動作（開啟流程、開啟經驗、切換探索篩選、前往分享、開啟辦理進度），不能產生任意路由
17. 待確認操作：會寫入資料的要求（例如「幫我開始辦這個流程」）先產生待確認操作，5 分鐘到期；使用者確認後重新檢查權限才寫入；訪客不能寫入
18. 存取控制與成本：登入才能用（開發環境例外；訪客是否開放【待確認】）、頻率限制、每日用量上限、Gemini 失敗時給安全的備用回覆；金鑰只放後端

**AI 助理語意搜尋（RAG）**
19. 向量資料：Cloud SQL 啟用 pgvector，建立文件、段落與向量的資料表（透過 B 的 migration 機制）
20. 使用者內容語意搜尋：一般使用者發布的公開內容（學生經驗、辦理回報裡的原話，以及之後新增的貼文類型）發布後自動用 Gemini embedding 轉成向量並建立索引，助理馬上找得到；修改時重建，隱藏、刪除、被檢舉下架或帳號刪除時立即從索引移除；索引不含作者資訊
21. 官方文件檢索：收集流程卡的官方來源文件，切段、轉成向量，記錄來源與文件日期；過期文件停用
22. 語意搜尋工具：接進助理的工具呼叫；回答附出處（官方文件寫名稱、段落、日期；使用者內容寫「學生分享」與發布日期）；使用者內容標示為未經驗證的個人經驗，排在已驗證流程卡與官方來源之後；使用者內容裡的文字只當資料，不當指令；和已驗證流程卡說法不同時，以流程卡為準並提醒使用者向學校確認

**AI 助理測試**
23. 助理自動測試：工具呼叫、確認流程、帳號隔離、Gemini 失敗備援
24. 檢索品質測試：檢查語意搜尋找到的段落是否正確、有沒有漏掉相關內容

## 二、B 負責的工作

**資料層**
1. 用 Alembic 建立 migration 機制，以 database/schema_postgres.sql 為第一版（之後改表都用 migration），並把 test_schema.py 的測試搬成 pytest
2. 補 schema 還沒有的表：檢舉、封鎖、管理者操作紀錄、助理待確認操作
3. 建測試資料：匯入 flutter_app/assets/data 的示範經驗與流程

**後端核心**
4. 後端骨架：在 repo 新增 backend/，用 Python 3.12＋FastAPI、uv 管理套件、SQLAlchemy 連 Cloud SQL；路由結構、輸入驗證、統一錯誤格式、日誌、請求頻率限制
5. API 規格文件（OpenAPI）
6. 登入串接：驗證登入服務的 token、建立使用者（只存登入服務識別碼，不存密碼）
7. 權限：訪客、學生、reviewer、admin 四種；對外匿名，API 不回傳作者識別碼

**生活經驗**
8. 經驗草稿：建立、編輯、2000 字上限、空白驗證
9. AI 經驗摘要：原文 → 情境、感受或嘗試、給下一位的提醒；保存模型名稱；失敗重試、每日上限；畫面標示為 AI 整理
10. 發布流程：作者確認 AI 摘要後才能發布；原文改過要重新產生摘要再確認
11. AI 翻譯：中英互譯，綁定摘要版本，原文永遠保留
12. 探索：主題與身分篩選、分頁，只回傳公開欄位
13. 經驗詳情與「我的經驗不同」（新經驗連回原文）
14. 反應：有幫助、我也遇過（每人每篇每種最多一次，可取消）
15. 我的經驗：我的分享清單、影響數字（不同讀者數與反應次數分開計算）
16. 關鍵字搜尋經驗與流程（AI 助理的搜尋工具也用這支；語意搜尋由 A 負責）

**帳號與上架要求**
17. 刪除帳號與所有資料（含助理對話），含帳號刪除網頁
18. 檢舉：經驗與回報可被檢舉，被檢舉內容可隱藏（Google Play 使用者內容政策要求）
19. 封鎖其他使用者（同上）

**其他**
20. 寫開發環境安裝說明
21. 後端自動測試：權限、匿名不外洩、發布門檻、反應去重
22. AI 摘要品質測試：用 20 則真實分享逐則檢查摘要是否忠於原文、有沒有把經驗寫成事實
23. 準備 Google 審查用測試帳號

## 四、D 負責的工作

**制度流程（後端）**
1. 流程與版本：新增流程、建立新版本、發布後凍結內容（改內容要開新版本）
2. 來源與驗證：來源管理、審查紀錄、五種驗證狀態（unverified、community_supported、needs_review、verified、outdated）；沒有來源與審查紀錄不能標 verified
3. 辦理紀錄：開始辦理（綁定當時的版本）、步驟進度、結果（成功、未完成、流程不同、放棄）
4. 回報：卡關（要指定步驟）、流程不同、可能過時，含差異類型
5. 流程統計：近 30 天成功回報數、各步驟卡關回報數；沒有樣本時不顯示比例
6. 管理後端：提供 C 管理畫面需要的 API（流程編輯與發布、回報審查），並記錄管理者操作
7. 回報整理（P1）：用 AI 把多筆卡關與差異回報摘要給管理者，由管理者決定是否更新流程；AI 不能自動改流程或標驗證

**內容**
8. 第一批流程內容：依 PMP 高頻問題整理 8 張（工作證、ARC、健保、開銀行帳戶、在學證明、請假、綁定逢甲銀行帳戶、補辦學生證／ARC），每張附官方來源，並透過管理介面（或匯入檔）輸入系統

**上架**
9. 申請 Play 開發者帳號並完成身分驗證
10. 開內部測試與封閉測試軌道，邀請試用者加入（個人開發者帳號須至少 12 位測試者連續測試 14 天，才能申請正式版）
11. 寫隱私權政策（含 Gemini 處理分享原文與助理對話、對外匿名的說明）、服務條款、社群規範
12. 填資料安全表單、內容分級、廣告聲明
13. 寫商店頁中英文案，整理圖示與截圖
14. 送審正式版，處理退件

**測試與營運**
15. 寫手動測試清單（含 320／375／768／1024／1440 寬度與文字放大）
16. 寫 PMP 試用任務腳本（找相似經驗、分享一句話、確認 AI 摘要、問助理一個辦事問題、照流程辦一件事並回報結果）
17. 助理品質測試：用 20 題 PMP 常見問題逐題檢查答案、依據與驗證狀態是否正確，有問題回報給 A
18. 日常處理檢舉與待審回報
19. 整理成效數據給成果報告（指標見 experience-led-mvp 的 MVP Success Signals）
